# 경영권분쟁 스크리닝 (DART 5% 대량보유보고)

DART 공시통합검색 D001 `주식등의대량보유상황보고서` 전수를 받아, 경영권 영향
목적(경영권 분쟁·행동주의) 후보 종목을 자동으로 좁혀내는 파이프라인.

## 데이터

- `d001.csv` — 원천. 2026.06.01~2026.09.08 접수분 **4,010건** 전수
  (컬럼: `market, company, report, filer, date, rcp`)
- `5%공시_스크리닝_v1.xlsx` — 초기 탐색본(지분분산/기관 반복매집/미리캐피탈/RAW)
- `경영권분쟁_스크리닝_v2.xlsx` — 본 파이프라인 산출물 (아래 참조)

## 스크리닝 논리

1. **1차 필터 — 보고서식**
   - `약식` = 전문투자자/기관의 단순·일반투자 목적 → 경영권 무관, **제외**
   - `일반` = 그 외 전부. 경영권 영향 목적이면 반드시 일반서식 → **후보군**
   - 4,010건 → 일반(정정 포함) **2,926건**
2. **2차 신호 — 구조 스코어** (보유목적 프록시)
   - 한 종목에 서로 다른 보고자가 여러 명 일반보고 = 블록 경합 (분쟁 구도) ×3
   - 전략투자자(개인/사업회사) 존재 +2 · 정정보고 +2 · 단일 보고자 3회+ 매집 +1
   - **보유목적 확정 시** 경영참여/경영권 문구 1건당 +5

일반보고자 ≥2 로 경합하는 종목 **106개**가 1차 후보. 상위에는 한미사이언스,
삼진제약, 케이카, 디어유 등 실제 분쟁/행동주의 구도가 그대로 올라온다.

## 실행

```bash
pip install pandas openpyxl requests beautifulsoup4 lxml

```

### 보유목적 확정 (로컬 전용)

서식은 보유목적의 **프록시**일 뿐이다. 확정 판정에는 보고 본문/사유 텍스트가
필요하다. 웹 컨테이너에서는 `dart.fss.or.kr` · `opendart.fss.or.kr` 이 모두
egress 정책으로 차단되므로(우회 안 함) **로컬에서** 다음을 실행한다.

```bash
# 키를 screening/.env 에 저장 (하드코딩 금지, .gitignore 에 포함됨)
echo 'DART_API_KEY=<키>' > screening/.env

python dart_holding_purpose.py             # -> detail_purpose.csv 생성
python screen_control_disputes.py          # rcp(접수번호) 기준 자동 join, 확정 +5 반영
```

`dart_holding_purpose.py` 는 두 경로를 지원한다(`.env` 자동 로드):

- **`USE_API=True`(기본, 권장)** — OpenDART API. `corpCode.xml` 로 종목명→고유번호를
  자동 매핑(`corp_map.csv` 캐시)한 뒤 `majorstock` 을 받아 접수번호·보고사유·
  보유비율·직전비율을 한 번에 수집. 종목당 1콜(≈1,197콜).
- **`USE_API=False`** — 키 없을 때 웹 스크래핑. 본문 `보유목적`(경영참여/단순투자)
  분류까지 뽑지만 일반보고 2,926건을 개별 조회해 느리고 스로틀링 위험.

두 경로 모두 `rcp`(접수번호) 컬럼을 내보내므로 스크린이 동일하게 join 한다.
판별 문구는 `보유목적`(웹) 또는 `보고사유`(API)에서 `경영권|경영참여` 를 찾는다.

## 한계

- 서식 기반은 프록시. 최종 판정은 본문 `보유목적` 필요 (위 로컬 절차).
- 특수관계인은 각자 별도 보고 → 보고자 다수가 반드시 경합은 아님(한 편일 수
  있음). 최종 확인은 개별 종목 단위로.
